# Plan — T-4 (branch `feature/T-4-walk`, worktree `../VSCode-LLM-Tutorial-T-4`, cut from `main` after T-3 merges)

Verify: unit tests — round-trip from disk; `treeModel` statuses; next/prev at the ends.
2. **`src/walk/step-view.ts`** (no `vscode`). `renderStepHtml(state, skins)` where `state = { plan, progress, step, fileExists, note?: string, skin }`: the question; options — the author's marked *what the author did*, alternatives listed with consequence and a *coming with T-10* tag; why with its source label (`interpret` → "from the model, reading the code"; `docstring` → "from the author's own comment"; `none` → "not inferable from the source"); witness sentence or "no history to show"; the dial (three radios, current value); *Previous* / *Open the file* (disabled with a visible reason when `!fileExists`) / *Check my work* / *Next*; a `note` line (where replies land); the skin picker. Client script posts `step:*`, `dial:set`, `skin:set`, and re-applies a `note` via `restore()`. Verify: unit — one render per `whySource`, null witness, `fileExists` false; the script parses (`new Function`) and runs against the fake-DOM harness T-3 built (`test/unit/start-view.test.ts` pattern).
3. **`src/walk/step-protocol.ts`** (no `vscode`). `handleStepMessage(state, msg, effects)` → `{ state, post? }`; effects: `goTo(id)`, `openFile()`, `persistDial(stepId, dial)`, `persistSkin(name)`. `step:check` → `note: "Check my work arrives with T-5"` (honest, in the panel). Verify: unit tests per message.
4. **Adapters.** `src/walk/tree.ts` (`DecisionsTreeProvider`: chapters collapsible, steps as leaves with `$(check)` / `$(arrow-right)` / `$(circle-outline)` icons, `command: buildTutorials.goToStep` with the id; `refresh()` via an `EventEmitter`); `src/walk/step-panel.ts` (`WebviewViewProvider`: `resolveWebviewView` sets `enableScripts`, renders from the session, re-renders on `onDidChangeVisibility`, forwards messages to the protocol); `src/walk/editor.ts` (`revealStep`: `openTextDocument(join(target, step.target.file))`, `showTextDocument(doc, { preserveFocus: true, viewColumn: ViewColumn.One })`, reveal `startLine` in center, decorate every `scaffold.loadBearing` range for `symbol`/`file` steps; `clearDecorations`); `src/walk/status.ts` (status bar item `step N / M · <dial>`). Verify: typecheck; vscode-test in step 7.
5. **`src/walk/session.ts`.** `WalkSession.open(context, target, deps)` loads plan + progress, creates tree/panel/status, reveals the current step; `goTo(id)` sets current, persists, refreshes tree, re-renders panel, reveals editor; `next`/`prev`; `setDial`; `markDone` (used by T-5); `dispose` clears decorations. One instance per window; a second `open` on a different target replaces the first. Verify: unit test of the state machine with fake adapters; vscode-test end-to-end.

On activation: if `workspace.workspaceFolders[0]` has `hasPlan()` → open the walk at the saved position. After a successful build: if the target is the open workspace → open the walk; else `showInformationMessage('Plan built — open the folder to start?', 'Open the folder')` → `vscode.openFolder`. Verify: activation test still green; the walk opens on a workspace containing a plan.
