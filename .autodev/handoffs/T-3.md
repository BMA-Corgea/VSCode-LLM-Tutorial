## Surprises / judgment calls worth flagging to a reviewer

1. **AC2's idea-honesty rule, broadened beyond the plan's literal shorthand.** The plan
   (`.autodev/plans/T-3.md` step 4) writes the rule as `!recreate && idea && !repo`. Spec AC2's
   own wording ("typing an idea without ticking recreate shows...") does not condition on
   `repo`. Implemented as `!recreate` (regardless of `repo`) always produces an idea-field
   message — either the T-9 line (idea typed) or "say what you want to build, or tick
   recreate" (idea empty) — reasoned in `src/start/request.ts`'s `validateIdea` comment: v1's
   `BuildPlan.mode` is always `'recreate'`, so unticking recreate is a dead end regardless of
   what else is filled in, and the plan's literal shorthand would silently swallow the
   idea+repo+unticked case rather than naming it (exactly the "no silent decline" lesson AC2
   cites). Flagging for review rather than treating it as obviously settled.
2. **AC4's resume test is simulated, not a literal process kill.** "Kill vscode-test mid-build;
   on restart the marker is picked up" is tested two ways instead: (a) `test/unit/build.test.ts`
   proves the marker is durably written to disk at each phase transition, independently
   re-read from disk (not from in-memory state) inside the test; (b) a marker is hand-written
   to simulate a crash, and `resumeIfMarked` is called directly (the same function activation
   would call after a real reload) with a stubbed confirm. A literal kill of a nested
   vscode-test subprocess from within this suite was judged not worth the added fragility for
   the marginal proof it would add over (a)+(b) — flagging so a reviewer can decide if that's
   sufficient.
3. **`build.ts` has no `vscode` import at all**, extending the `core.ts`/`doctor.ts` house
   style. Every VS Code-specific effect (progress, cancellation, the Resume/Discard prompt,
   `globalStorageUri`, `workspaceState`) is a plain injected parameter, wired by
   `extension.ts`/`panel.ts`. This means the ENTIRE write-ahead marker, language refusal, and
   end-to-end fixture build (AC3, AC4, AC5) run under plain `mocha`, not vscode-test — faster
   and not dependent on a real extension host, but a larger design decision than the locate
   file explicitly called for, so noted here rather than left implicit.
4. **A failed (thrown) digest/buildPlan/interpretPlan/write step LEAVES the marker** rather
   than deleting it (only a deterministic language refusal or an explicit cancel deletes it) —
   reasoned as: a transient failure might be worth retrying, since digest/buildPlan cost
   nothing to redo and interpretPlan's cache is keyed by content hash regardless. This is a
   judgment call beyond the plan's literal text and worth a reviewer's sign-off.
