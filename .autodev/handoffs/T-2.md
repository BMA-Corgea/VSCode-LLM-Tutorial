## Surprises / where the plan and reality diverged (flagged per instructions, not silently changed)

1. **`vsce package` cannot ship repo-tour as a dependency, full stop — not a config problem.**
   The plan's CI step explicitly said "NO: dependencies must ship... so plain `vsce package`."
   Tried that first; it hard-errors:
   `invalid relative path: extension/../repo-tour/node_modules/@types/node/zlib.d.ts`.
   repo-tour is a `file:../repo-tour` **sibling** checkout, so walking into its own
   `node_modules` (for `web-tree-sitter`/`tree-sitter-wasms`, ~150MB, and it pulls in
   repo-tour's devDependencies too since a plain `npm install` doesn't separate them on disk)
   produces paths that escape the `.vsix`'s own root — not representable in the archive,
   symlink or not. This is not a `.vscodeignore` problem; there is no ignore pattern that lets
   *some* of a sibling directory's files in while keeping the archive's paths valid. Changed
   `npm run package` to `vsce package --no-dependencies` (28KB, clean). The packaged extension
   still expects a sibling repo-tour checkout at run time — exactly like `./build-tutorials
   dev` already requires. This matches spec §11's own explicit deferral ("Publishing repo-tour
   to npm / vendoring it into the .vsix — deferred... a public artifact is not v1"); it is a
   T-8 concern, not a T-2 gap. `ci.yml`'s comment documents this with the exact error.
2. **AC5's "matching repo-tour's practice" doesn't quite match what repo-tour does.** Read
   repo-tour's actual practice before writing this: `LICENSE.txt`, a "## Licence" section in
   `README.md`, and a live **Source** link rendered in its served HTML footer
   (`src/server.ts`) — but **no per-file SPDX headers anywhere in `src/*.ts`, and no `NOTICE`
   file**. T-2's locate/plan are more specific than the spec text here (locate's touched set
   names `NOTICE`; plan step 9 says "SPDX headers on `src/*.ts`"), so I followed the
   plan — `NOTICE` and SPDX headers exist here even though repo-tour itself carries neither.
   Surfacing this rather than silently picking one reading: if the intent was literally "copy
   repo-tour's approach," the correct shape would have been LICENSE + a README section +
   (eventually) an in-app Source link and nothing per-file. What's built now is a superset,
   not a contradiction, so I did not treat it as a stall — flagging it here as instructed.
3. **The ledger snapshot under `.autodev/tickets/T-2-....json`** (read-only, never edited)
   shows `"stage": "refine"` and `"gates": {"spec_ready": false, ...}` as of when I started,
   which looks stale against the dispatch instructions I was given ("Gate: spec_ready — spent
   by Evan's in-session go-ahead") and against `.autodev/locates/T-2.md` +
   `.autodev/plans/T-2.md` already existing on disk (later pipeline stages). Not something I
   touched or tried to reconcile — noting it only in case it is useful signal; my dispatch
   instructions were unambiguous that building was authorized, so I built.
